# 0039-test-add-sora-dependent-e2e

- Priority: Low
- Created: 2026-06-08
- Model: deepseek-v4-pro

## 目的

Sora サーバーを必要とする e2e テストのシナリオを拡充し、実際の接続時のエラーハンドリングや再接続、デバッグペインのデータ表示など、サーバーとのインタラクションが必要なシナリオをカバーする。

## 優先度根拠

Sora サーバーが利用可能な環境が限定されるため優先度は低いが、実際の WebRTC 接続を伴うリグレッションを検出するためには必要。Phase 1 の基盤整備（#0037）が完了してから着手する想定。

## 現状

- 正常系の接続テスト（`sendrecv`, `sendonly`, `recvonly`）のみ存在する
- エラーハンドリングのテストがない（存在しないチャンネル ID、無効なトークン等）
- 切断後の再接続テストがない
- 接続中のデバッグペイン（ログ・シグナリング・通知）の表示検証がない
- simulcast / spotlight の数値的検証がない

## 設計方針

`tests/pages/DevtoolsPage.ts`（#0037 で導入）を利用し、Playwright の `expect` API も活用して以下のテストを追加する。

追加するテスト:

1. **エラーハンドリング**
   - 存在しないチャンネル ID で接続した場合、エラーメッセージが表示されること
   - 接続失敗時にアラートが表示され、UI が適切な状態に戻ること
2. **再接続**
   - 正常に接続 → 切断 → 再度接続 のサイクルが動作すること
   - 接続失敗 → 再接続 が可能であること
3. # デバッグペインの表示検証
   - 接続成功時にデバッグペインの Timeline タブにイベントが表示されること
   - 接続成功時に Signaling タブにシグナリング情報が表示されること
   - Notify タブに Sora からの通知が表示されること

## 完了条件

- 上記 3 つのカテゴリのテストが `tests/` に追加されている
- Sora サーバーが利用可能な環境で `pnpm test:e2e` が全テストを通過すること
- 環境変数未設定時は skip されること（#0037 の仕組みを利用）

## 解決方法

1. `tests/error-handling.test.ts` を新規作成
2. `tests/reconnect.test.ts` を新規作成
3. `tests/debug-pane-display.test.ts` を新規作成
